# 语音与 ComfyUI 迁移后的独立分层复审

2026-11-14，WSL 主审核者。实施由 NAS 本机 Codex 完成；本文依据最终源码、独立行为复测和项目检查形成，不以实施者的自评代替验收。范围是源码迁移与离线验收，正式配置、旧状态和生产部署尚未应用。

## 结论

保留 Pi、Bot、Plugin 三层。Pi 负责模型请求、工具循环、会话和压缩；Bot 负责可信身份、授权、资源、持久任务、执行预算、产物和平台交付；插件负责语音与绘图业务。本次两个迁移已经形成可构建、可打包、可恢复的实际链路，未发现仍阻塞这两条链路的明显问题。

独立接受的证据：Core **178 tests / 1333 assertions**、插件 **66 tests / 709 assertions**，均零失败；11 个有效 T/C 边界脚本通过，检查、构建、插件格式与四包双次字节比较通过。真实包通过自编 Worker/RPC/Job、memory/JSONL 和假服务执行；没有新增数据库测试。NAS 的累计补丁及连续增量均从已接受的 T 基线回放相等。最终提交、包摘要与检查日志由交接收据单独记录，避免本文自引用哈希。

## 已修复的实际问题

| 问题 | 最终处理与复核 |
| --- | --- |
| 呈现 Job 容量已满使成功正文丢失；封存回退后、发送前退出不能恢复 | 明确拒绝写入原幂等接纳键，原 Outbox 发送一次文字；没有父 Run 的 prepared 回退也可恢复。未知接纳单独保留，不冒充拒绝或重新抽概率 |
| 长语音占满执行资源，控制指令不能响应 | 数据挂载与调度分类分离，后台预留前台容量；单 Worker 自动呈现提交前回退文字。后台调用链不能借前台操作声明升格 |
| 无消费者仍逐项鉴权；普通回复重复保存大恢复快照 | 按消费者声明查询能力；无消费者额外鉴权为 0。仅实际选择异步呈现才捕获快照；1500 能力样例从约 42 KB 降为约 0.6 KB，快照调用为 0 |
| `-n` 被当作数量、保留默认 LoRA 实际覆盖默认、多触发词候选被猜选 | 负词与数量别名恢复正确语义；保留活跃默认后分配空槽；只使用明确候选、默认提示或唯一候选。每工作流、受管节点步数覆盖相互隔离 |
| 部分成功的未知余项不能继续核对；pending 核对又清空已有产物 | `businessStatus`、`factsComplete` 与平台 `delivery` 分开；外部结果按 item/Artifact 单调合并。独立复测为 1 图+未知 → pending 查询仍 1 图 → 最终 2 图，总 POST 仍为 2，未新增聊天消息 |
| 同范围无数据后台操作与前台查询共用串行锁，抵消预留容量 | Core 可信前后台类别进入无数据 Worker 的 lane/key。前台查询可在后台 HTTP 等待时完成；总 Worker/内存预算不变，后台继承、重入、清理和无私有文件边界保持 |

对应实现主要在 `pkgs/runtime/src/delivery.ts`、`pkgs/jobs/src/external/outcome.ts`、`pkgs/plugins/src/jobs/runner.ts`、`pkgs/plugins/pkgs/runtime/src/`、`pkgs/plugins/src/hooks/` 与 Comfy 插件业务模块。pending 呈现的部分索引与查询谓词已核对一致，避免控制/恢复依赖扫描全部房间历史；没有为此添加数据库测试。

## Bot 层现在提供了什么

| 能力 | 对插件编排的实际作用 |
| --- | --- |
| `gsvi@1`、`comfy@1` 具名协议与允许参数的资源快照 | Core 代管凭据、固定端点、模板摘要、参数范围和来源。插件使用别名与结构化业务参数，不取得宿主路径或任意网络能力 |
| scope / instance CAS 状态 | 群偏好与实例全局锁分别持久化，版本冲突与额度有明确结果。插件不靠模块全局变量、跨范围私有文件或原始数据库维持共享状态 |
| execute / poll / recover / cancel 与持久远端所有权 | Core 在 Worker 回执之前保存 `prompt_id`；同进程回执丢失、重启和缺少 handle 可核对原任务。逐 item 原服务、模板/参数摘要、请求 JSON 与产物归属保留，未知提交不自动重发 |
| 业务结果、远端事实、平台交付分开记账 | 一个批次可部分成功并仍待核对；查询不清掉成功结果，不重新发送已确认内容。手动核对也刷新模型可见的 JobFacts |
| typed direct / forward、逐 part ACK 与唯一 Outbox | 插件不构造平台原生对象。平台不支持 forward 时发送前降级；发送结果未知不切格式重发。实际 16 项取得 16 份产物和 16 个 ACK，重启不重复 |
| 受管异步呈现、可信来源和模型历史投影 | TTS 只改发送副本，保留 Pi 原文；结构化 forward/附件整条 mixed。绘图历史开关通过公开 Pi 扩展过滤本实例工具参数，包括 `start_job` 入口，保留原审计与恢复记录 |
| 执行与网络预算、分页及管理入口 | 无数据前后台并发不突破总 Worker 预算；HTTP 全局 4、每服务 2、下载 2。大目录分页/Artifact 不放宽 RPC 帧上限；真实资源、绑定和任务组件已有浏览器证据 |

调试 ring20、不可变 Core 回执、模型可见历史是三个不同生命周期。`pop` 或关闭 history 不删除恢复依据，也不意味着原始审计被擦除。

## Bot 层仍缺少的支持

这些是后续插件扩展的实际缺口，不是本次迁移已经提供的 API。

1. **插件实例与状态的受管升级生命周期。** 固定代码/资源版本和撤销检查已有，但准备、数据迁移、排空旧任务、回滚和销毁尚无完整公共协议。升级不能只替换文件并假设旧 Job、私有状态仍兼容。
2. **带所有权的订阅、插件计划与交互。** 现有核心计划和持久观察不等于插件可注册 Cron、外部订阅、任意 observe→Job 或持久用户确认。需要继承来源授权、幂等键、停用行为和唯一交付所有者。
3. **完整的有效编排诊断。** 当前能看处理器顺序与部分绑定信息，仍不能完整解释某个 scope 下因 selector、权限、grant、服务版本或依赖缺失而被排除的节点。
4. **更广的结构化消息与按实际需求扩展的领域服务。** 现在提供 direct/forward/Artifact；任意 mention、quote、交互回调、跨范围发送，以及 STT/视觉/知识检索等并未因此自动获得支持。
5. **继续抽离 Invocation 装配。** Coordinator 仍承担较多入口与上下文装配。后续可抽出共同的 Bot Invocation 工厂，避免新的插件能力继续依赖 Agent DTO 或向 Coordinator 堆业务逻辑。

## Plugin 层还缺少什么，为什么会影响编排

| 声明缺口 | 对编排的影响与建议 |
| --- | --- |
| 通用效果、重放与资源占用语义 | 前后台、actions 和阶段 schema 已有，仍不能据此判断任意第三方代码是否只读、可重试、能取消或争用同一资源。后续需要受 Core 接纳的最小效果/恢复/资源声明，不能凭 JSON schema 自动重放 |
| 可组合的输出槽位和冲突策略 | 当前主呈现器适合选择一个输出；图卡、语音、字幕与附件的保留、替换、附加关系尚不足以表达。仅调整 priority 不能解决重复消费或重复交付 |
| 能力版本、依赖条件与生命周期需求 | 已有服务协议和显式绑定，但复杂插件仍需要说明恢复、状态版本、可用特性和条件依赖。安装、配置、可执行和可恢复应分别给出诊断 |
| 与执行一致的有效编排图 | UI 排序不是执行计划证明。应能看到实际输入来源、授权天花板、资源版本、持久对象所有者、未知结果的核对路径和最终发送者 |

本次不引入第二个 Agent、通用效果 DSL 或完整工作流引擎。先保持两个真实业务闭环，再用下一类实际插件验证上述缺口。

## 接受范围与生产边界

源码与离线验收完成，生产迁移尚未执行。13 个 API 工作流和 6 个 LoRA 配套文件只读生成了待审候选，原 SHA 不变；候选不证明生产模型/自定义节点/GPU 兼容。正式 root0600 配置、旧 KV、管理员/群/别名映射没有读取或应用。

Comfy 运行任务没有 per-prompt GPU 取消保证；无 ID 的未知提交不重提，只有已确认属于本任务的排队项可请求精确删除。服务 URL、凭据、策略或授权变化停止旧任务，旧 ID 不交给新服务。平台总媒体预算仍适用，16 个小图的通过不能推导为任意 256 张大图都能发送。

未提供任意宿主扫描、上传/img2img、WS 收图或跨服务接管。未修改既有容器/生产服务/正式后端，未发送真实 QQ、TTS、付费模型或 GPU 请求，未执行 root/sudo、push 或部署。后续上线需以明确目标和实际配置另行实施。
