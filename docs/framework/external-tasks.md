# 持久外部任务与 Cron

MCP Tasks、插件后台操作和 Cron 使用统一的 Job、权限、取消与交付机制。Pi durable 保存任务阶段与恢复状态，Bot 管理远端协议和平台副作用。

## MCP Tasks

服务声明 `tasks.requests.tools.call`，且工具声明 `execution.taskSupport` 时才使用标准任务协议：

- `required` 工具自动转为后台 Job。
- `optional` 工具默认短调用，可用 `start_job` 明确转后台，也可在服务配置中调整自动策略。
- 每个服务可配置等待任务上限、轮询间隔和连续查询失败上限。

执行分为提交、等待、读取结果和交付。提交前保存检查点；取得远端任务 ID 后，用原 ID 和固定连接配置继续查询。等待期间释放主会话与模型请求额度，重启后可以恢复。

只读查询可以有限重试。未收到提交回执、远端会话丢失或连接中断时，系统不会重新创建任务；会话恢复后也只查询原 ID。远端句柄和 HTTP 会话保存在私有状态中，不返回给模型或普通 API 投影。

本地停止等待、远端确认取消和回执未知是不同状态。网页中的「核对远端状态」与「取消远端任务」只使用已保存的 ID，不创建新工作，也不重复发送聊天结果。没有远端 ID 的未知提交只能保留待核对状态。

二进制结果保存为 Artifact，并沿用范围、媒体预算和交付账本。对普通非 Tasks 工具，Bot 不会根据响应文本猜测远端任务协议。

## Cron

每次计划触发保存计划 ID、触发键、原定时间、IANA 时区、创建者和能力上限。同一触发键只受理一次，相同计划及其未结束的孩子不会重叠执行。停机期间尚未受理的触发默认跳过，不积累补发。

上下文模式：

- **独立上下文**：创建子 conversation，工作区按计划复用；子任务全部结束后统一交付。
- **共享主对话**：使用范围的当前上下文和工作区，长操作可继续转交后台 Job。

「暂停自动执行」只影响未来触发；「停止本次工作」取消当前运行及其孩子；删除计划会先停止新的受理，再取消已有工作。

已受理任务使用固定配置快照，后续触发使用最新设置。工具权限仍受创建者上限和当前规则约束，新增资源不会自动授予已有计划。

协议参考：[MCP Tasks](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks)。
