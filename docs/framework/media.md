# 会话媒体、引用与视觉输入

媒体处理分为平台引用、范围内缓存和单次模型请求投影。发送者与图片来源只用于归属和权限判断，不共享其调用权限。

## 输入与缓存

- OneBot 数组和 CQ 字符串解析为文字、媒体引用和回复 ID；普通消息先记录，不立即下载所有附件。
- Mock 支持上传附件和引用已有消息。
- 私有媒体记录保存平台文件标识与签名 URL，模型只接收媒体 ID、授权元数据和本轮需要的图片。
- 浏览器查看或 Agent 读取时按需下载，并缓存在当前范围的 Artifact Store。

默认每次模型请求最多附带 4 张图片，最长边 1536 像素，Base64 总量 4 MiB。图片能力不足的候选会被跳过；纯文字后续请求不会重复携带上一轮的像素。

## 读取与沙盒传递

`media_read` 接受当前范围的 `media` 或 `artifact` ID，不接受任意 URL 或宿主路径。`stage=true` 额外需要 `write` 权限，并把文件放入当前沙盒的 `/workspace/.bot-media/`；后台 Agent 使用自己的工作区。

QQ 非标准媒体服务可在连接设置中登记 HTTP(S) origin。每次重定向都重新核对来源，下载不会转发 Provider 或 NapCat 凭据。平台返回的文件名不会作为宿主文件路径读取。

## 引用与撤回

优先使用当前范围已记录的引用。未观察到的 QQ 消息可通过 `get_msg` 查询，但响应必须能证明属于当前群或私聊；无法确认时不拼接其他范围内容。

已撤回来源不再自动投影。一个逻辑回复对应多个平台回执时，撤回状态逐条记录；撤回聊天消息不会删除此前已生成的任务产物。

音频、视频和普通文件保留为可下载附件，也可按权限传入沙盒。内置视觉输入面向图片，不将附件保存等同于语音识别或视频理解。
