# Bot 框架

框架围绕共享会话、有效配置、可信权限、持久任务和统一交付组织。各专题文档描述运行行为；插件作者以 [插件开发手册](../plugins/README.md) 为准。

## 职责边界

| 层 | 职责 |
| --- | --- |
| Pi | 模型请求、工具循环、会话与压缩、后台 Agent |
| Bot | 消息入口、可信身份、配置、资源、权限、Job、产物与平台交付 |
| 插件 | 业务操作、指令、Hook 和私有数据，通过公开 RPC 与 Bot 协作 |
| MCP / Skill | 分别提供远程工具和按需加载的说明、脚本及资源 |

Provider 管理连接和模型候选；Shipyard 管理 Agent 的文件与 Shell 工作区。它们与插件 Worker 是不同的执行域。

## 会话与有效配置

聊天范围由平台、机器人账号和群/私聊地址确定，拥有多个 conversation 和一个当前选择。群成员共享当前上下文与偏好，不自动获得彼此的工具权限。

配置按默认、账号、聊天范围、当前 conversation 逐层合并。受理时固定人格、资源和配置版本；取消、实例停用与权限撤销在实际操作和交付前继续检查。多人合批使用共同允许的能力，不选择其中一位成员作为高权限代表。

详见 [会话范围与触发人权限](conversation-scope.md)。

## 任务与交付

- 主 conversation 保持单个活动推理，短窗口内的消息可有界合批。
- 后台 Agent 与外部长操作使用独立 Job，必要时使用独立 conversation 和工作区。
- MCP Tasks、插件后台操作和 Cron 复用持久提交、等待、取消与结果交付机制。
- 原始模型文字、实际呈现内容和平台回执分别保存。
- 外部提交或发送结果未知时不自动重做，避免重复副作用。

详见 [外部任务与 Cron](external-tasks.md)。

## 能力与资源

工具权限使用稳定 ID，模型使用的别名不参与授权。内置工具、MCP、Skill 和插件操作先经资源选择及授权过滤，再由全量或按需搜索策略装载；隐藏工具不等于撤销权限，搜索也不能启用未授权资源。

配置状态与运行状态分开：已安装、已启用、已选择、资源可用、当轮已装载和实际调用是不同事实。工作台的诊断用于解释具体阻塞原因。

## 执行与数据边界

Agent 文件和 Shell 操作委托给配置的 Shipyard/Bay 后端，不在失败时回退宿主。插件业务在独立 Worker 中执行，网络默认关闭，代码只读，私有数据按实例与聊天范围隔离。

原始消息、模型输入投影、用户可见输出和平台回执是不同视图。媒体引用和长工具结果使用受管 ID 与 Artifact，不把签名 URL、宿主路径或大块二进制放进模型上下文。

通用运行配置见 [部署配置](../configuration.md)。插件卷、产物额度和备份见 [插件存储](plugin-storage.md)。
